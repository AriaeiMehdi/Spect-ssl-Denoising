# 2. Fix 1 — SSL queue accumulation regression

## Problem

The current accumulated SSL runner stores representations in something equivalent to:

```python
queued_values = []
```

and appends values over gradient-accumulation batches.

After a successful optimizer step, these values are inserted into the representation queue, but the temporary list is not reliably cleared afterward.

This causes previous accumulation windows to be inserted repeatedly.

For example:

```text
window 1 → A
window 2 → A+B
window 3 → A+B+C
```

instead of:

```text
window 1 → A
window 2 → B
window 3 → C
```

This corrupts:

* queue composition;
* queue occupancy;
* variance statistics;
* effective-rank calculations;
* participation rank;
* correlation diagnostics;
* any queue-supported SSL regularization.

This is a **blocking bug**.

---

## 2.1 Refactor optimizer-window finalization

Primary file:

```text
src/gated_spect/training/runner.py
```

Avoid maintaining separate subtly different implementations for:

* normal accumulation completion;
* partial final accumulation;
* AMP-success;
* AMP-skip.

Create a shared internal helper if practical.

Its responsibilities should be:

1. unscale gradients when AMP is active;
2. perform gradient clipping;
3. attempt optimizer update;
4. determine whether optimizer step succeeded;
5. update EMA teacher only after a successful optimizer step;
6. insert only representations belonging to the current accumulation window;
7. increment `optimizer_steps` only after success;
8. increment `optimizer_step_skips` after failure;
9. clear temporary queued representations regardless of success/failure;
10. reset accumulation state.

Required lifecycle:

```python
successful_step = ...

if successful_step:
    ema_teacher.update(model.backbone)

    if queued_values:
        consistency_head.queue.enqueue(
            torch.cat(queued_values, dim=0)
        )

    optimizer_steps += 1
else:
    optimizer_step_skips += 1

queued_values.clear()
```

The temporary representation buffer must therefore be empty before the next accumulation window starts.

---

## 2.2 Failed AMP windows

If AMP skips an optimizer update:

```text
student optimizer state → unchanged
EMA teacher → unchanged
representation queue → unchanged
optimizer_steps → unchanged
optimizer_step_skips → +1
```

Representations generated by that failed optimizer window must be discarded.

# 3. Fix 2 — Correct the optional covariance/correlation regularizer

## Problem

The current covariance penalty operates directly on raw covariance and may use only the current two SSL representations.

That creates two problems:

1. raw covariance magnitude depends on representation scale;
2. two samples cannot provide a useful covariance estimate for a 256-dimensional representation.

---

## 3.1 Preserve the existing corrected diagnostics

Do not modify the already-correct:

```text
SVD effective rank
participation rank
off-diagonal correlation metrics
feature-standard-deviation metrics
queue capacity = 2048
```

unless required to fix an actual bug.

The change applies to the **optional training regularizer**, not the representation diagnostics.

---

## 3.2 Use queue-supported sample statistics

Construct the regularizer from:

```text
current differentiable representations
+
detached historical queue representations
```

For example:

```python
history = consistency_head.queue.values().detach()
current = projected_current

z = torch.cat(
    [history, current],
    dim=0,
)
```

Historical representations must never receive gradients.

---

## 3.3 Introduce minimum sample support

Add a configurable or documented value:

```text
covariance_min_samples = 512
```

If:

```text
N < covariance_min_samples
```

return:

```text
loss = 0
ready = false
```

Do not estimate a 256-D correlation structure from only a few samples.

---

## 3.4 Standardize features before decorrelation

For each representation component:

[
\hat Z_j =
\frac{Z_j-\mu_j}
{\sigma_j+\epsilon}
]

Then calculate the feature correlation matrix:

[
R =
\frac{\hat Z^T\hat Z}
{N-1}.
]

Penalize only off-diagonal terms:

[
L_{\text{corr}}
===============

\frac{1}{D(D-1)}
\sum_{i\neq j}
R_{ij}^{2}.
]

The result should be approximately invariant to global feature scaling.

---

## 3.5 Required tests

Add:

### Duplicate-feature test

```python
x = torch.randn(N, 1)
z = x.repeat(1, 256)
```

Expected:

```text
high correlation penalty
effective rank ≈ 1
```

### Independent-feature test

Random independent features should have substantially lower correlation penalty.

### Scale-invariance test

Verify approximately:

```text
loss(z)
≈ loss(0.01 * z)
≈ loss(100 * z)
```

### Gradient-isolation test

Queue history:

```text
no gradient
```

Current representations:

```text
gradient exists
```

### Warm-up test

Below `covariance_min_samples`:

```text
loss = 0
ready = false
```
